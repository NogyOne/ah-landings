## Documentation Policy

- Document current behavior from verified evidence.
- Keep planned or accepted design intent clearly separate from implementation truth.
- Link to the canonical owner instead of duplicating content.
- Add `decisions/`, `patterns/`, `runbooks/`, or acceptance documentation only when a real decision, reusable pattern, operational procedure, or acceptance contract exists.
- Do not create empty documentation structures.
